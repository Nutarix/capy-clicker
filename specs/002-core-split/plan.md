# 002 — План: разрез ядра и плавность

Спека: [`spec.md`](spec.md). Шаги: [`tasks.md`](tasks.md).

## Коротко

- Сначала отпечаток поведения (Т12), снятый на старом коде. Дальше каждый шаг сверяется с ним побайтно.
- `GameController` — фасад с прежним API. Правила живут в частях `lib/features/game/core/`, у каждой своё поле ответственности и свои поля состояния. Общий `GameCore` держит `GameState`, часы, сид и цепочку проверок.
- Уведомление одно (`ChangeNotifier`), но экран слушает его через `GameSelector`: виджет пересчитывает маленькое значение (record из показанных полей) и перестраивается, только если оно изменилось. Новой зависимости нет.
- Разовые сообщения — поток `events`. Экран больше не опрашивает поля после каждого уведомления.
- Ход, где сдвинулась только шкала, не гоняет цепочку проверок.
- Новых зависимостей нет.

## Т2. Фасад

`GameController extends ChangeNotifier` с прежними конструктором, геттерами и методами. Каждый член — одна строка делегирования в часть. `notifyListeners` передаётся в `GameCore` как `onNotify`. ~330 строк.

Уходят (никто не читает ни в `lib/`, ни в тестах):

| Член | Почему |
|---|---|
| `lastRoleToast`, `acknowledgeRoleToast` | экран его не показывал; теперь событие `RoleAssigned` |
| `isAnyBoostActive`, `activeBoostRemainingSeconds` | остатки старого HUD |
| `placeAt`, `isOverPlace` | экран считает места по раскладке луга (`MeadowOccupancy`) |
| сеттеры `lastTapGrass`, `lastDroppedFood` | поля стали геттерами, снаружи их не писали |

Добавляется `Stream<GameEvent> events`.

## Т3. Быстрый путь шкалы

`commit` (бывший `_setState`) гоняет цепочку: обрезка по поляне, трава/уют ≥ 0, «был в тумане», слоты ролей и тент по науке, близнецы, круги полян, туман, цели. Каждое звено — функция полей, кроме `herdProgress`, и после одного прохода состояние — неподвижная точка цепочки: повторный проход ничего не меняет (обрезка идемпотентна, круг/туман/цели сдвигаются до первого невыполненного, близнецы чистятся до согласованных).

`GameCore` помнит флаг `normalized`: состояние вышло из `commit`. Любое прямое присваивание (`core.state = ...`: загрузка, авто-трава, близнецы, трава с цветка) снимает флаг.

`GameHerd.addProgress`: если никто не появился и флаг стоит — `state.copyWith(herdProgress: p)`, уведомление, запись по таймеру. Иначе — полный `commit`. Результат тот же: полный проход над неподвижной точкой, где изменился только `herdProgress`, вернул бы то же значение (а `copyWith(herdProgress:)` так же пересобирает `meadows[active]`). `Random` в цепочке не вызывается, тостов неподвижная точка не даёт.

Попутно (значения те же, меняется только тождество объектов): `addProgress` без появления не копирует список семьи, обрезка по поляне оставляет прежний список и прежних капи, если никто не сдвинулся. Так «список семьи тот же» значит «семья не менялась» — на это опираются селекторы экрана.

## Т4. События

`GameMessages` держит слоты разовых сообщений (`puddleToast`, `gladeUnlockToast` + трава, `goalCompleteToast`, роль, оффлайн) и флаг «ещё не отправлено». Геттеры и `acknowledge*` прежние (на них тесты и симуляции).

`GameCore.notify()`: `notifyListeners()`, потом `messages.flush()` — отправляет неотправленное в том же порядке, в каком экран раньше опрашивал: оффлайн, утренний уют, поляна, лужа, цель, роль. Поэтому порядок плашек прежний, и если поляна и туман открылись в одном ходе, плашка одна (последний текст), как раньше.

- Оффлайн уходит только при `ready` — как условие `isReady && hasOfflineWelcome` у экрана.
- Утренний уют: событие при переходе «недоступен → доступен» (сброс в начале `init`). Экран, как и раньше, показывает лист один раз за вход.
- Нет слушателя — слот ждёт (как поле ждало экрана).

Экран (`GameMessagesMixin`) на событие делает то же, что делал на опрос: `acknowledge*`, звук, плашка в следующем кадре.

Поток `broadcast(sync: true)`: обработка в том же вызове, как раньше в `notifyListeners`.

## Т5. Запись без разбора

`GamePersistence._save`: строка `raw` проверяется на читаемость не `jsonDecode(raw)`, а `GameState.fromJson(map)` по тому же `map`, из которого она закодирована. Разбора JSON на записи нет. `jsonEncode` → `jsonDecode` для наших данных даёт ту же структуру (числа и строки как есть), поэтому «читается обратно» означает то же. В копию по-прежнему попадает только проверенная строка; `load`, отложенные битые данные и порядок записи не меняются. Первая запись сессии, как и раньше, проверяет текущий основной перед тем, как сделать его копией.

## Т6. Экран по частям

`GameSelector<T>` (`widgets/game_selector.dart`): слушает контроллер, на уведомление считает `select()`, `setState` только при `!=`. Значение — record из того, что виджет показывает (record сравнивается по полям; списки — по тождеству, а оно теперь меняется только с содержимым).

| Часть | Перестраивается, когда меняется |
|---|---|
| корень `GameScreen` | готовность, поляна, земля; оверлеи карты/ракеты/земель |
| верхняя плашка | трава, строка места/цели |
| нижняя панель | трава, «позвать» и почему нет, ускорение |
| луг (`MeadowLayer`) | семья, близнецы, лужа, валяние, ускорение лужи, вспышка, ягода, декор, тент, магнит; размер луга |
| маркер места (каждый) | активен, откат, видимые секунды отката |
| кнопка утреннего уюта | доступность |
| карта леса, земли (когда открыты) | показанные числа |

Шкалы прогресса на экране сейчас нет (`CreamProgressBar` не подключён) — частый ход трогает только то, что правда изменилось.

Капи берут начало луга в глобальных координатах лениво, в момент перетаскивания (`meadowOriginGlobal` стал функцией): раньше значение обновлялось каждым тиком, теперь перестроек мало, а камера может плавно отъезжать.

## Т7. «Уют»

## Риски

- Пропущенное поле в селекторе — часть экрана не обновится. Страховка: селекторы собирают ровно то, что читает `build`; ручная игра; тесты виджетов.
- Время-зависимые значения (откат места, конец ускорения, полночь) обновляются по уведомлению тика, как и раньше: пока игра идёт, тик уведомляет каждые 50 мс.
- Быстрый путь держится на флаге `normalized`. Новый код, который пишет `core.state` напрямую, обязан пройти через сеттер (он снимает флаг). Отпечаток и `live_tick` это ловят.
- Тождество списков как признак изменения: если кто-то начнёт менять список семьи на месте, селектор не заметит. В коде списки неизменяемы по договорённости (`copyWith`).
