# 005 — Сборка для магазина

Ветка: `005-store-build` от `main`. WBS: 1.5.5, 1.5.6. Можно вести параллельно с 001–004: ядро игры не трогает.

## Что изменится для игрока

- Шрифты игры всегда на месте. Сейчас Nunito и Pixelify Sans скачиваются из интернета при запуске, а в релизной сборке Android у игры даже нет разрешения на интернет. Поэтому без сети, а в релизе и вовсе, игра показывает стандартный шрифт вместо пиксельного. После спеки шрифты лежат внутри игры.
- Игра весит меньше: из сборки уходят неиспользуемые картинки, около 5 МБ.
- Игру можно выложить в Google Play на внутреннее тестирование.

Больше ничего в игре не меняется.

## Почему

- Релизная сборка Android подписана отладочным ключом. Google Play такую не примет.
- Шрифты из сети: см. выше. Заодно игра обращается к серверам Google, о чём пришлось бы писать в анкете безопасности данных магазина.
- Нет автоматической проверки: анализатор и тесты запускаются только руками.
- В сборку попадают `app_icon.png` (660 КБ, в игре не используется) и `bg_forest.png` (4,6 МБ, нужен только как запасной фон при ошибке).

## Сценарии

### С1. Игра без сети (P1)

- Дано: телефон в режиме полёта, игра установлена из релизной сборки.
- Когда: игрок запускает игру.
- Тогда: заголовок и кнопки — пиксельный Pixelify Sans, остальной текст — Nunito, как в отладочной сборке.

### С2. Сборка для Google Play (P1)

- Дано: у Никиты есть ключ загрузки (создаётся по инструкции из этой спеки) и файл с его паролями, которого нет в репозитории.
- Когда: собирается релиз.
- Тогда: получается подписанный этим ключом файл `.aab`, который принимает консоль Google Play на внутреннее тестирование.
- Дано: ключа нет (чистая машина, CI).
- Тогда: отладочная и тестовая сборки собираются как раньше; релизная сборка не подписывается молча отладочным ключом, а явно сообщает, что ключа нет.

### С3. Автопроверка (P1)

- Когда: открыт PR в `main` или в `main` пришёл коммит.
- Тогда: на GitHub автоматически проходят `flutter analyze` и `flutter test`. Красная проверка видна в PR.

### С4. Ключи не утекают (P1)

- Ключ, пароли, собранные `.apk`, `.aab`, `.ipa` не попадают в git.

## Требования

### Шрифты

- **Т1.** Nunito и Pixelify Sans лежат в ассетах игры вместе с их лицензиями (обе под SIL Open Font License). Только нужные начертания.
- **Т2.** Скачивание шрифтов во время работы выключено. Внешний вид текста не меняется.
- **Т3.** Тесты используют шрифты из ассетов и не ходят в сеть. Если спека 001 уже это сделала по-своему — согласовать, не дублировать.

### Подпись и сборка Android

- **Т4.** Релиз подписывается ключом загрузки из `android/key.properties` (вне git). Без ключа релизная сборка явно падает с понятным сообщением, а не подписывается отладочным ключом.
- **Т5.** Инструкция `store/RELEASE.md` по-русски: как создать ключ загрузки, куда положить, как собрать `.aab`, как поднять версию в `pubspec.yaml`, как выложить на внутреннее тестирование. С пометкой включить подписание приложений Google Play (Play App Signing). Ключ и пароли создаёт и хранит Никита, Claude их не видит.
- **Т6.** Убрать устаревший шаблонный TODO про application id. Идентификатор `com.nutarix.capy_clicker` остаётся: после первой загрузки в магазин его нельзя будет поменять. Это записать в `RELEASE.md`.
- **Т7.** Память для Gradle — разумная для обычной машины и CI, а не 8 ГБ.

### Размер

- **Т8.** Из ассетов игры убрать `assets/images/app_icon.png`: в коде не используется, иконка приложения берётся из `store/icon/`.
- **Т9.** Запасной фон при ошибке — один из фонов полян, а не отдельный `bg_forest.png` на 4,6 МБ. Файл убрать из ассетов.

### Автопроверка

- **Т10.** GitHub Actions: на PR и на push в `main` — установить Flutter той же версии, что в проекте, `flutter analyze`, `flutter test`. Без сборки релиза и без секретов.

### Порядок в репозитории

- **Т11.** В `.gitignore` добавить `*.apk`, `*.aab`, `*.ipa`. Устаревший `store/GrowCapy-1.0.1+2-arm64-v8a.apk.sha256` удалить.
- **Т12.** iOS, без сборки: в `Info.plist` iPad только в портрете, как iPhone; ключ об отсутствии нестандартного шифрования (`ITSAppUsesNonExemptEncryption = false`), чтобы App Store не спрашивал при каждой загрузке.
- **Т13.** Веб: цвета манифеста и значок вкладки — из иконки игры (кремовый и зелёный), а не синие стандартные Flutter.

## Вне рамок

- Финальные скриншоты и текст страницы магазина: игра сильно изменится к 1.0, снимаем в конце.
- Английский текст страницы — спека 013.
- Сборка и публикация в App Store: нужен Mac и аккаунт разработчика Apple. Здесь только подготовка `Info.plist`.
- Подпись релиза в CI с секретами — когда понадобится автоматическая выкладка.
- Перенос тяжёлых файлов `store/emulator`, `store/art-pack-*` из репозитория — отдельное решение.

## Нужно решить Никите

1. **Магазины для 1.0:** только Google Play, или ещё App Store? От этого зависит, нужен ли Mac и аккаунт Apple. Спека готовит iOS, но не собирает.
2. **Политика конфиденциальности.** Google Play просит её для игр с детской аудиторией и для анкеты безопасности данных. Игра ничего не собирает, страница простая. Где её разместить: GitHub Pages этого репозитория или отдельная страница? Сделать её в этой спеке?
3. **Лицензия кода:** закрытая («все права защищены») или открытая? Репозиторий публичный, без файла лицензии код по умолчанию закрыт, но лучше сказать это явно.

## Критерии приёмки

- Релизная сборка без сети показывает правильные шрифты (Никита проверяет на телефоне в режиме полёта).
- `flutter build appbundle --release` с ключом даёт подписанный `.aab`; без ключа — понятная ошибка.
- PR показывает зелёную проверку GitHub Actions.
- `flutter analyze` без замечаний, `flutter test` зелёный и без сетевых запросов за шрифтами.
- Размер `.aab` меньше текущего примерно на 5 МБ.
