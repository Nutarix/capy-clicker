# Спеки разработки

Каждая крупная правка — своя спека и своя ветка от `main`. План игры — [`docs/WBS.md`](../docs/WBS.md), имена — [`docs/NAMES.md`](../docs/NAMES.md).

## Как идёт спека

1. Claude пишет `specs/NNN-имя/spec.md`: что меняется для игрока, сценарии, критерии приёмки. Без технических деталей в верхней части.
2. Никита утверждает спеку по короткому описанию «что изменится в игре».
3. Сабагент в ветке `NNN-имя` пишет `plan.md` (как сделать) и `tasks.md` (шаги), потом по шагам: сначала тест, потом код. Перед сдачей — `flutter analyze` без замечаний и `flutter test` зелёный.
4. Claude ревьюит код и тесты, открывает PR в `main`.
5. Никита играет сборку и сливает PR.

Новые спрайты: когда спеке нужен арт, Claude даёт подробное описание, что нарисовать. Никита генерирует, Claude обрабатывает и подключает. Без серых заглушек (`docs/ART.md`).

Параллельно идут только спеки, которые не трогают ядро игры (`GameController`, `GameState`, сейв). Ядро — строго по очереди.
